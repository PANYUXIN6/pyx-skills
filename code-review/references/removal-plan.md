# 移除与迭代计划

只有证据表明代码未使用、重复、已被替代、永久禁用或造成真实风险时，才提出移除候选项。先搜索静态引用，再考虑动态加载、反射、外部使用者和运行时配置。

## 可以立即安全移除

仅在能够证明没有活跃使用者、且移除范围可验证时使用此类别。逐项说明：

- 位置和职责；
- 未使用或已被替代的证据；
- 影响范围；
- 最小移除步骤；
- 必须更新的测试、配置或文档；
- 验证方法。

## 推迟移除

若外部使用者、迁移、监控或团队确认是前置条件，不要建议立即移除。应提供：

- 推迟原因与当前风险；
- 必要前提；
- 兼容或迁移步骤；
- 验证指标和观察窗口；
- 回滚计划。

## 报告约束

- 不要把“看起来没用”当作移除证据。
- 不要建议顺手删除与当前变更无关的既有无用代码；有帮助时可单独列为剩余风险。
- 移除计划必须保护外部契约、数据迁移和可恢复性。
